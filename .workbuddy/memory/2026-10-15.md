## tile-merger v1.0.0（新建项目）

- 参照 `E:/workspace/har-gen-api`（har-gen-api，GitHub lemonppai/har-genapi 已 404）的技术约定实现瓦片图层合并工具
- **参照项目约定**：TS + ESM（type:module）、esbuild `bundle:true` 单入口打包到 `dist/index.js`（避免 ESM 相对导入扩展名问题）、`bin/cli.js` shebang + cfonts banner、chalk@5 + inquirer@14 + log-symbols、原生系统选择对话框（powershell/osascript/zenity）、构建后校验产物无相对导入
- **关键技术点**：
  - inquirer v14 无具名导出（只有 `createPromptModule`/`default`），list 类型名为 `select`（不是 `list`）；已封装 `src/ui/ask.ts`
  - Windows 下动态 `import(绝对路径)` 会报 `ERR_UNSUPPORTED_ESM_URL_SCHEME`，必须用 `pathToFileURL().href`
  - 本机 npm 装包时 esbuild postinstall spawn node.exe 报 EBUSY → 用 `npm install --ignore-scripts`（esbuild/sharp 均有预编译平台包，无需构建脚本）
  - `--tms`/`--pattern` 是全局坐标约定，对所有图层统一生效
- **架构**：`src/core/{types,source,pattern,scan,layout,merge}` + `src/ui/{ask,logger,dialog,browser}` + `src/index.ts`（parseArgs + generate 向导）
- **合并算法**：单块 RGBA Uint8Array 画布，逐瓦片 sharp 解码为 raw，不透明瓦片走直接覆盖快速通道（hasTransparency 探测），带透明瓦片按 source-over 混合，越界自动裁剪；JPEG 输出用 flatten 压平
- **验证**：`npm test` 12/12 通过（dir/zip、遮挡顺序、x_y 扁平命名、TMS、pattern、JPEG 底图、JPEG 输出、空洞统计、后缀推断、错误路径、no-overwrite）
- 已知限制：单张完整图片输出，内存 ≈ 宽×高×4；zip 用 adm-zip 整包载入内存

## tile-merger v1.1.0（输出模式改造）

- 用户需求变更：默认输出改为**按坐标目录结构的合并瓦片**（如 `out/3/1/2.png`），不再需要输入输出文件名
- `mergeTiles` 增加 `mode: 'tiles' | 'single'`，`tiles` 为默认；`--single` 保留整图输出（`-n` 仅该模式需要）
- 瓦片模式实现：按坐标分组（`collectCells`）→ 逐格建单瓦片画布 → 逐层 source-over 叠加 → 并发写盘（`pool` 并发池，默认 min(8, cpus)）；内存从 O(全图) 降到 O(单瓦片)
- 输出目录结构跟随输入：带 z 输出 `{z}/{x}/{y}.png`，二维输入输出 `{x}/{y}.png`（`layoutTemplate` 会代入实际 z 值）
- 空瓦片策略：无覆盖格不生成；完全透明的瓦片默认跳过（`--keep-empty` 保留）；`--no-overwrite` 时已存在瓦片跳过并计入 warnings
- **测试坑**：2D 布局下 x=3 会生成目录 `3/`，不能断言"路径不以 3/ 开头"，应校验路径深度（`/^\d+\/\d+\.png$/`）
- **环境坑**：本机沙箱 safe-delete 垫片拦截 `fs.rmSync` 走回收站，偶发 `ETIMEDOUT` → tests/make-fixtures.mjs 的清理逻辑降级为逐目录删除 + try/catch
- 测试扩到 18/18：新增瓦片目录结构、zip 与文件夹逐字节一致、2D 结构、透明跳过、keep-empty、no-overwrite、瓦片/单图逐像素等价

## tile-merger v1.2.0（层级 z 保留修复 + 输出结构可自定义）

- 用户反馈输出只剩 `{x}/{y}.png`；确认（AskUserQuestion）目标输出结构为 `{z}/{x}/{y}.png`
- **根因**：`buildPlan` 用 `new Set(layers.map(l => l.z))` 判定层级，任何一个图层没有 z（2D 目录）或各图层 z 不一致就把 `plan.z` 置 null，输出整体退化成 `{x}/{y}.png`
- **修复**：层级改为从**瓦片级**收集（`plan.zooms` 升序集合）——只要有一个瓦片带 z 就保留；2D 图层的瓦片并入同坐标的层级格一起叠加；同坐标多层级（如 z=3、z=4）拆成多张分别输出到各自的 z 目录（`collectCells` 重写：先按 (x,y) 分组，组内按 z 拆分，flat 瓦片并入最低层级并按 layerIndex 重排保证叠加顺序）
- 新增 `--out-layout`（API `outLayout`）自定义输出结构模板，支持 `{z}/{x}/{y}/{ext}`；`normalizeOutLayout` 校验（必须含 {x}{y}、禁 `..`、非法字符、未知占位符）；`applyLayout` 热路径展开
- `MergeTilesResult` 新增 `zooms` 字段；`layout` 在多层级时显示 `混合（3/{x}/{y}.png、4/{x}/{y}.png）`；`layoutTemplate(zoom, format, outLayout?)` 的 zoom 支持 `'any'`（保留 {z} 占位）
- 测试扩到 23/23：混合 2D+3D 保留 z、多层级分别输出、outLayout 自定义/去层级/非法报错/{ext}
- **工具坑**：Edit 工具对同时含反引号和 `${...}` 的多行 old_string 匹配异常（`{y}` 被改写成 `${y}`）；规避方案：Write 写代码片段文件 + Node 脚本按锚点 splice（锚点选无花括号的注释行），或拆成不含 `${}` 的单行小编辑
